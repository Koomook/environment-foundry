# Founder Daily Loop

Status: active operating protocol

The daily loop turns one piece of company learning into four connected outputs. It is not four separate jobs.

```text
calendar + communications
→ one priority and one falsifiable question
→ experiment or evidence review
→ company version delta
→ linked public note
→ conversations and objections
→ feedback ledger
→ next question
```

## Minimum viable day

| Block | Timebox | Output |
|---|---:|---|
| Calendar and communications sweep | 15 min | Today's fixed commitments, owed replies, and top three actions |
| Evidence block | 60–90 min | One experiment, review, or decision—not general research |
| Version delta | 20 min | `OBSERVED / HYPOTHESIS / NOT YET / NEXT GATE` |
| Linked note | 20–30 min | One public-safe idea derived from the delta |
| Feedback capture | 2 min per conversation | Objection, request, evidence type, permission, next action |
| Close | 15 min | Due dates and tomorrow's first action |

On event, hospital, travel, or family days, the evidence block may be skipped. A `HOLD` version plus one captured conversation is a valid day.

## Daily version contract

Each version answers only six questions:

1. What changed since yesterday?
2. What was directly observed?
3. Which interpretation remains a hypothesis?
4. What is still not demonstrated?
5. Which decision or experiment comes next?
6. What would make us narrow or stop?

Do not create a new deck every day. The daily artifact is usually one page. A deck is produced only for a real audience or decision.

## Linked publishing rule

The public note is downstream of evidence, not an independent content quota.

- Never convert a proposed threshold into a measured result.
- Never publish private company, participant, or communications data.
- Use the day's strongest tension, observation, or changed belief.
- End with one question that can produce useful disagreement.
- Store reader responses as feedback, not as proof.

## Communication sweep

Read-only triage order:

1. Today's calendar and travel/setup time.
2. Unanswered direct messages with explicit promises or dates.
3. Gmail requiring a decision, document, payment, or attendance.
4. Team channels that change ownership or deadlines.
5. Everything else goes to a weekly review, not today's list.

The output is an action ledger. Raw private messages remain in their source systems.

## Capacity rule

- Maximum two 90-minute deep-work blocks on an ordinary weekday.
- Maximum one 60–90-minute block on a travel, family, hospital, or event day.
- Sleep, exercise, family anchors, and travel/setup are scheduled before optional research.
- If a new urgent obligation appears, remove a task of comparable size; do not silently extend the day.
