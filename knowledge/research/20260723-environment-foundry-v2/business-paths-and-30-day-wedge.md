# Two business paths and a 30-day falsification wedge

Status: recommendation, not canonical strategy

## Path A — improve existing benchmark scores

Product: expert-authored tasks, graders, traces, and hardening services for an
existing benchmark or buyer-owned environment.

| Dimension | Implication |
|---|---|
| Time to first proof | Days to weeks |
| Buyer acceptance | Existing score, task validity, exploitation tests |
| Moat | Domain experts, verifier quality, private holdouts, production speed |
| Revenue shape | Project/task supply; possibly managed eval renewal |
| Main risk | Commodity task production and benchmark overfitting |
| Best first customer | Agent team with a named failed workflow and frozen acceptance test |

This is the safer cash-and-learning path. It directly exercises compiler and
grader skill but does not prove a new category.

## Path B — create company-operation environments

Product: rights-valid prospective decision episodes, delayed outcome closure,
replay, and eventually interactive environments for one real operation.

| Dimension | Implication |
|---|---|
| Time to first proof | Weeks to months |
| Buyer acceptance | outcome-adjusted lift, intervention reduction, transfer, rights |
| Moat | access contract + prospective instrumentation + outcome closure + compiler |
| Revenue shape | managed environment, longitudinal refresh, outcome/eval service |
| Main risk | data labor, causal overclaim, rights failure, no buyer budget |
| Best first principal | operator who receives immediate workflow value and controls the task |

This is the mission path, but it must earn entry through utility and validity.

## Recommendation

Run Path A as a constrained apprenticeship and revenue probe while Path B
dogfoods one prospective task. Do not merge their evidence. A benchmark task
delivery can prove production capability; it cannot prove real company outcome
validity.

## 30-day wedge

Task: post-event commitment reconciliation.

Agent surface:

```text
frozen approved note
→ extract counterparty role, commitment, owner, due date, evidence
→ abstain/escalate on missing authority or third-party rights
→ human approves all outbound changes
→ 7/30-day fulfillment and harm outcome
```

No participant contact, autonomous outbound action, or sensitive Git payload is
authorized by this plan.

## Pre-registered arms

1. human-only;
2. generic model with the same visible note;
3. generic model + private retrieval + deterministic workflow rules;
4. environment rehearsal or SFT only after a clean train/holdout split exists.

## Day-by-day gates

| Day | Artifact | Pass | Kill / narrow |
|---|---|---|---|
| 1–3 | task + rights contract | two operators reproduce fields and cutoff; ambiguity fails closed | rights or observation cutoff cannot be frozen |
| 4–7 | grader calibration | severe-failure agreement 100%; rubric agreement target ≥0.80 | grader can be gamed or reviewers disagree on severe failures |
| 8–21 | 20 shadow episodes | zero unauthorized action; provenance 100%; outcome-closure plan for all | any material privacy/harm event; data labor not measured |
| 22–27 | held-out operator | no accuracy/harm regression; ≥20% median time reduction target | benefit disappears outside designer |
| 28–30 | buyer spec / economics | three buyer-written specs or one cost-covering design pilot | only curiosity; no acceptance test or budget owner |

## Decision vector

Continue environment-category work only if all are true:

- participant/operator receives measurable net value;
- rules/retrieval baseline leaves a meaningful error or judgment gap;
- rights permit the claimed use and deletion propagates;
- outcome closure is cheaper than the value created;
- held-out ranking is stable enough to guide a system change.

If the rules baseline wins, ship workflow software. If buyer demand exists only
for task/grader production, pursue Path A. If real outcomes cannot be closed,
stop simulator language.
