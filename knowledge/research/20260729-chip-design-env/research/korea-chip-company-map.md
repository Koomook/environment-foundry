## 파트 2: 데이터 보유 추정

> 이하는 공개 정보 + 업계 구조에 대한 **추론**이다. 실제 보유 여부는 각사 확인 필요.

### 유형별 데이터 자산 매트릭스

| 유형 | RTL/넷리스트 | 검증 스위트 | PPA 로그 | 테이프아웃 이력 | PDK 계약 | 고객 프로젝트 메타데이터 |
|---|---|---|---|---|---|---|
| 팹리스 AI 칩 | ◎ 자사 핵심 자산 | ◎ (성능/전력 벤치 포함) | ◎ 1~2개 노드에 집중 | ○ 1~3회/사 | 직접 또는 디자인하우스 경유 | △ 자사 제품 위주 |
| 디자인하우스 | △ (소유권은 고객) | ◎ 재사용 검증 인프라 | ◎ **프로젝트×노드 교차 데이터** | ◎ 연 수십 건 | 파운드리 공식 파트너로 직접 계약 | **◎ 유형 중 최대** |
| IP 벤더 | ◎ IP 단위 RTL | ◎ IP별 검증 스위트 | ◎ 노드별 IP PPA | ◎ 테스트칩 + 고객 실리콘 피드백 | 다중 파운드리(삼성+TSMC) | ○ 라이선스 고객 다수 |
| 중견 팹리스(차량/MCU/PMIC) | ◎ 자사 | ◎ 차량은 AEC-Q100/ISO 26262 인증 데이터 | ○ 성숙 노드 위주 | ◎ 다품종 다회 | 직접 | △ |

### 핵심 추론

1. **디자인하우스가 '데이터 허브'다.** 세미파이브·에이디테크놀로지·에이직랜드 등은 연간 수십 개 고객 프로젝트를 수행하며 (a) 노드×IP조합×PPA 결과, (b) 설계 산출물의 스펙-구현-검증 이력, (c) 테이프아웃 성공/실패 원인, (d) 파운드리 수율 피드백을 **조직적으로 축적**한다. 단, RTL/최종 GDS의 소유권은 대개 고객(팹리스)에 있고, 디자인하우스에는 **프로세스 지식 + 메타데이터 + 자체 재사용 블록**이 남는 구조가 일반적이다. 세미파이브의 "플랫폼 재사용" 모델은 이 축적을 명시적으로 제품화한 사례다.

2. **팹리스 AI 칩사의 데이터는 '깊지만 좁다'.** 리벨리온·퓨리오사는 특정 노드(삼성 5nm급, 미확정)에서 2~3회 테이프아웃의 고품질 데이터(아키텍처 탐색 로그, 워크로드별 PPA, 컴파일러-하드웨어 코디자인 이력)를 가진다. RL 환경 관점에서 "칩 한 개를 깊이 최적화하는 에피소드" 데이터로 가치가 높다. 특히 컴파일러/SDK 스택(퓨리오사, 리벨리온 모두 자체 스택)은 아키텍처 결정의 결과를 소프트웨어 성능으로 추적 가능하게 한다.

3. **IP 벤더는 '검증된 블록 단위' 데이터.** 칩스앤미디어·퀄리타스·오픈엣지는 IP별로 다중 노드/다중 고객 실리콘 피드백을 가진다. 블록 단위라 비식별화·권리 분리가 상대적으로 쉬워 **데이터 거래의 단위 경제성이 가장 좋은 유형**일 수 있다.

4. **차량용 플레이어(텔레칩스, 넥스트칩, 보스반도체)는 프로세스 컴플라이언스 데이터.** ISO 26262(기능안전), AEC-Q100 인증 이력은 "규제 환경에서의 설계"라는 별도 RL 환경 차원을 제공한다.

5. **PDK 접근 구조**: 팹리스 대부분은 파운드리와 직접 NDA/PDK 계약을 맺거나, 디자인하우스(DSP/VCA)를 통해 간접 접근한다. 삼성 SAFE DSP(세미파이브, 에이디테크놀로지, 가온칩스, 코아시아세미, 세솔반도체)와 TSMC VCA(에이직랜드)는 공식 파트너로서 PDK를 라이선스받아 고객 프로젝트에 사용하므로, **PDK 데이터 자체는 파운드리 소유이고 재배포 불가** — 이것이 데이터 파트너십의 최대 법적 제약이다.

  - **공동 연구/공동 특허**: 학계 연결(KAIST·서울대 SIPC 등 이미 활발)
  - **인재 파이프라인**: RL 환경 기반 설계 교육 프로그램, 신입 설계자 온보닝 시뮬레이터 — 인력난이 만성인 업계라 체감 가치 높음
- **권리 이슈**: 고객 IP 소유권(설계 용역 계약상 RTL/GDS는 고객 자산) → **메타데이터만 분리 제공하는 계약 설계 필요**. 파운드리 PDK NDA → PDK 파라미터 자체는 제외하고 "설계 의사결정 시퀀스"만 추상화. 에이직랜드(TSMC)는 TSMC NDA가 삼성보다 엄격한 편 (미확정)

#### B. 팹리스 AI 칩 (리벨리온, 퓨리오사, 딥엑스, 모빌린트, 보스반도체, 망고부스트, 팜네시아)
- **제공 가능 데이터(추정)**: 아키텍처 탐색(설계 공간 탐색 로그), 워크로드-PPA 트레이드오프, 컴파일러 코디자인 이력, 테이프아웃 전후 예측 vs 실측 갭
- **원할 만한 대가**:
  - **AI 도구 라이선스**: 검증 자동화, PPA 예측 모델 — 테이프아웃 1회 비용(수백억 원) 절감과 직결되어 페이백 명확
  - **공동 논문/벤치마크**: 스타트업에게 기술 신뢰도 마케팅 효과
  - 지분/전략 투자 연계 (대기업 CVC가 이미 활발하게 쓰는 수법)
- **권리 이슈**: 아키텍처 자체가 핵심 영업비밀이라 **원시 RTL 공유 가능성 낮음**. "실패한 설계 실험 로그"는 경쟁력 노출이 적어 협상 여지 있음. 투자자(SKT, KT 등) 이해관계 확인 필요

#### C. IP 벤더 (칩스앤미디어, 퀄리타스, 오픈엣지)
- **제공 가능 데이터(추정)**: IP 블록 단위 RTL+검증 스위트, 노드별 IP PPA, 고객 실리콘 피드백(계약상 회수 가능 범위 내)
- **원할 만한 대가**: IP 검증 자동화 도구(검증이 IP 벤더 원가의 큰 비중), 신규 표준(UCIe, APV) 대응 공동 연구, 해외 인재 채널
- **권리 이슈**: IP 자체가 상품이라 **라이선스 계약 구조가 이미 존재** → 데이터 라이선스로 확장하기 가장 쉬운 유형. 고객 피드백 데이터는 계약별 조항 확인 필요

#### D. 중견 팹리스 (텔레칩스, 실리콘마이터스, 넥스트칩, 어본트, 아나패스)
- **제공 가능 데이터(추정)**: 성숙 노드 다품종 테이프아웃 이력, 차량 인증(AEC-Q100, ISO 26262) 프로세스 데이터, 아날로그/전력 설계 노하우
- **원할 만한 대가**: 설계 자동화(성숙 노드라 자동화 효과 큼), 인재 파이프라인, 차량 기능안전 문서화 AI 도구
- **권리 이슈**: 상대적으로 보수적 조직 문화, 대기업 고객 NDA(현대·기아, 디스플레이 패널사)

### 3-3. 실행 우선순위 제안

1. **1순위: 세미파이브 + 에이직랜드(디자인하우스 2개사 POC)** — 프로젝트 메타데이터 밀도 최고, 상장사라 거버넌스 명확, "AI 설계 도구와 데이터의 교환"이라는 대칭적 딜 설계 가능
2. **2순위: IP 벤더 1곳(퀄리타스 또는 오픈엣지)** — 블록 단위 데이터라 권리 분리 용이, 비상장(퀄리타스)이라 의사결정 빠름
3. **3순위: 딥엑스/보스반도체(팹리스)** — 국책과제·공동연구 채널로 진입. 딥엑스는 NPU 개발자 생태계 사업을 이미 하고 있어 교육/환경 제공 명분이 맞음
4. **병행 트랙**: 삼성 SAFE 프로그램에 "AI 도구 파트너"로 진입 시도 — 생태계 전체에 노출되는 구조적 채널 (진입 난이도 높음, 미확정)

### 3-4. 공통 리스크
- **파운드리 PDK NDA**: 어떤 데이터셋도 PDK 파생 파라미터를 포함하면 파운드리 승인 필요 → 초기부터 "PDK-free 추상화" 설계
- **고객 IP 소유권**: 디자인하우스 데이터는 고객별 NDA 망 위에 있음 → 프로젝트 식별 불가 수준의 집계/익명화가 법적 최소선
- **경쟁사 노출 우려**: 동일 업종 복수사와 계약 시 상호 배타 조항 요구 가능
- **(미확정) 표기 수치 다수**: 비상장사 재무는 theVC/블로그 2차 출처 의존 — 실제 딜 전 실사(due diligence) 필요
