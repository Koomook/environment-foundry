# 공개 인터랙티브 학습 페이지 화면 명세

## 0. 한 줄 정의

**제목:** AI가 칩 설계를 배우려면 무엇이 필요한가?
**학습 목표:** 방문자가 5분 안에 “좋은 AI에는 코드 더미만이 아니라
시뮬레이터, 결정 데이터, 믿을 만한 피드백이 함께 필요하다”를 직접 발견한다.

공개 교육 페이지다. 회사 소개, 사업 전략, 파트너 선정, 데이터 확보 제안,
90일 실행 계획은 넣지 않는다.

## 1. 핵심 메시지

```text
Simulator = AI가 시도하고 결과를 볼 수 있는 연습장
Data      = 어떤 상황에서 무엇을 시도했고 어떻게 끝났는지 남긴 경험
Feedback  = 맞았는지, 안전한지, 더 나아졌는지 판단하는 채점
```

세 요소는 곱셈 관계다. 하나라도 0이면 학습 환경이 성립하지 않는다.

- 데이터만 있으면: 과거 파일을 흉내 낼 뿐, 행동의 결과를 배울 수 없다.
- 시뮬레이터만 있으면: 무엇을 연습해야 하는지와 좋은 출발점이 없다.
- 피드백이 약하면: AI는 칩이 아니라 점수의 빈틈을 최적화한다.

## 2. 전체 흐름

상단 고정 탐색은 네 항목만 둔다.

```text
세 가지 재료 · 진실의 사다리 · 점수의 함정 · 아직 모르는 것
```

스크롤 순서는 다음과 같다.

1. 질문으로 시작
2. 세 가지 재료 조립
3. simulator/data/feedback 사다리 탐색
4. reward hacking 미니 데모
5. 완성된 학습 루프
6. 공개 질문과 근거 경계

## 3. 화면별 명세

### 화면 A — Hero: “코드를 많이 읽으면 칩을 설계할 수 있을까?”

**헤드라인**

> AI가 칩 설계를 배우려면
> 코드보다 먼저, 연습할 세계가 필요합니다.

**서브카피**

> 칩은 문장이 아니라 물리적으로 동작해야 하는 물건입니다. AI가 설계를
> 바꾸면 무엇이 좋아지고 무엇이 깨졌는지 되돌려 주는 환경이 필요합니다.

**주 인터랙션**

“AI에게 무엇을 먼저 줄까요?” 카드 세 개를 제시한다.

- 수많은 설계 파일
- 빠른 시뮬레이터
- 정확한 채점표

하나를 클릭하면 “좋은 시작이지만 이것만으로는 부족합니다”와 빠진 두 요소가
빈 슬롯으로 나타난다. 세 카드를 모두 슬롯에 넣으면 다음 문장이 열린다.

> 이제 AI는 **보고 → 바꾸고 → 실행하고 → 피드백을 받아 → 다시 시도**할 수
> 있습니다.

CTA: `이 학습 루프를 따라가 보기 ↓`

### 화면 B — 세 가지 재료

가운데에 작은 칩 블록, 주변에 세 개의 클릭 가능한 원을 둔다.

#### 1. Simulator — “바꾸면 무슨 일이 일어나는가?”

- 쉬운 설명: 설계를 실행해 보는 연습장
- 예: 덧셈 결과, 테스트 실패, 회로 크기, 배선 충돌
- 빠른 도구 예: Icarus Verilog, Verilator, Yosys
- 더 현실에 가까운 도구 예: OpenROAD, FPGA, 실제 silicon
- 경고: 빠른 시뮬레이션 결과가 실제 칩 결과와 항상 같지는 않다.

#### 2. Data — “어떤 경험을 남겨야 하는가?”

- 약한 데이터: 완성된 RTL 파일만 모은 것
- 더 좋은 데이터:
  `문제 상황 → 당시 보인 정보 → 수정 → 도구 결과 → 채택/되돌림`
- 예: 실패한 테스트 seed, waveform, 수정 diff, 다시 돌린 regression
- 경고: 미래의 정답이나 숨은 테스트가 입력에 섞이면 학습이 아니라 답안 유출이다.

#### 3. Feedback — “무엇을 좋은 설계라고 부를 것인가?”

- 첫 번째 문: 기능이 맞는가?
- 두 번째 문: 안전 규칙과 물리 규칙을 지키는가?
- 그 다음 비교: 더 작고, 빠르고, 전력을 덜 쓰는가?
- 경고: 모든 항목을 점수 하나로 섞으면 기능을 버리고 면적만 줄이는 편법이
  생길 수 있다.

**상호작용**

각 원을 클릭할 때 중앙 루프의 해당 구간이 켜진다. 세 개가 모두 켜져야
“학습 가능한 환경” 배지가 나타난다. 색 외에 아이콘과 텍스트 상태를 함께 쓴다.

### 화면 C — 클릭 가능한 “진실의 사다리”

세로형 6단 사다리. 각 단을 클릭하면 오른쪽 패널에 같은 네 질문이 열린다.

```text
AI는 무엇을 바꾸나?
어디서 실행하나?
어떤 데이터가 남나?
무엇으로 채점하나?
```

| 단계 | 쉬운 이름 | Simulator | Data | Feedback | 반드시 보여줄 한계 |
|---|---|---|---|---|---|
| 1 | 기능 연습 | RTL simulation | 사양, RTL, test | 출력이 맞는가 | 테스트하지 않은 경우는 모른다 |
| 2 | 빈틈 찾기 | formal checker | assertion, counterexample | 모든 가능한 경우에 규칙을 지키는가 | 속성이 빠지면 그 행동은 검증하지 못한다 |
| 3 | 회로로 바꾸기 | synthesis | RTL, 제약, cell library | 기능 보존, 면적, 속도 | cell 수는 실제 배치 후 결과의 proxy다 |
| 4 | 칩 위에 놓기 | place & route | netlist, LEF/DEF, 배선 제약 | timing, congestion, DRC | 공개 PDK 결과가 첨단 공정을 대표하지 않는다 |
| 5 | 실제처럼 돌리기 | FPGA/emulation | workload, counter, trace | 실제 프로그램의 성능·전력 | FPGA와 최종 silicon은 다르다 |
| 6 | 현실에서 확인 | silicon/test | 측정치, 결함, 수율 | 실제 동작과 장기 결과 | 느리고 비싸며 권리가 복잡하다 |

**사다리 인터랙션**

- 기본 선택은 1단계.
- `빠름 ↔ 현실과 가까움` 축에서 위로 갈수록 시간·비용이 늘어나는 모습을
  길이로 표현한다.
- `한 단계로 충분할까?` 버튼을 누르면 다음 단계가 필요한 이유가 한 문장으로
  나타난다.
- 기술명은 보조 정보로 접어 두고, 첫 화면에는 쉬운 이름만 보인다.
- 6단계를 모두 연 뒤 요약:

> 좋은 환경은 가장 비싼 시뮬레이터 하나가 아니라, 빠른 피드백과 현실 검증을
> 연결한 사다리입니다.

### 화면 D — Reward hacking 미니 데모: “점수를 잘 받으면 정말 잘 설계한 걸까?”

기존 공개 실험의 관찰 결과를 쉬운 게임으로 재구성한다.

**문제**

> 작은 덧셈 회로를 만들어 주세요.

두 후보를 이름을 숨긴 채 고르게 한다.

- 후보 A: 예제에서 본 경우만 빠르게 처리하는 지름길
- 후보 B: 덧셈 규칙을 구현한 회로

#### Step 1 — 보이는 예제만 채점

`공개 예제 3개 실행` 버튼.

- A: 3/3 통과
- B: 3/3 통과
- 화면 질문: `둘 다 만점입니다. 같은 실력일까요?`

#### Step 2 — 숨은 경우 열기

사용자가 `숨은 1,024가지 경우 실행` 버튼을 누른다.

- A: 828가지에서 실패
- B: 모두 통과
- 실패 예시 한 개를 파형 대신 간단한 입력/예상/실제 카드로 보여준다.

#### Step 3 — 잘못된 점수 순서 체험

채점 순서를 토글한다.

```text
[나쁜 채점] 작은 회로에 먼저 점수 → 기능 실패도 높은 점수 가능
[좋은 채점] 기능 통과를 먼저 요구 → 그 안에서 크기·속도 비교
```

사용자가 나쁜 채점을 선택하면 “AI가 규칙을 어긴 것이 아니라, 우리가 잘못
정의한 점수를 정확히 최적화했습니다”라는 설명이 나온다.

**마무리 카피**

> 숨은 테스트도 완벽한 진실은 아닙니다. 테스트, 정형검증, 합성, 물리설계,
> 실제 측정을 차례로 연결해야 합니다.

데모에서 “AI가 속였다”라는 의인화 표현은 쓰지 않는다. 원인은 grader 설계의
빈틈으로 설명한다.

### 화면 E — 완성된 피드백 루프

한 개의 순환 다이어그램을 클릭 가능한 다섯 단계로 보여준다.

```text
1 관찰: 지금 볼 수 있는 사양과 실패
2 행동: 제한된 RTL 또는 설정 변경
3 실행: 고정된 도구·버전·조건에서 돌리기
4 채점: 기능 hard gate 뒤 품질 비교
5 기억: 성공과 실패, 반례, 되돌림을 함께 저장
```

각 단계를 누르면 “빠지면 생기는 일”이 나타난다.

- 관찰 경계 없음 → 미래 정답 유출
- 행동 경계 없음 → 채점기나 테스트 수정
- 실행 고정 없음 → 같은 설계의 점수가 매번 변함
- hard gate 없음 → 기능을 버리고 숫자만 개선
- 실패 기록 없음 → 같은 실패를 반복

마지막에는 용어 경계를 명시한다.

> 여기까지 만들면 **인터랙티브 학습 환경**입니다. 이 환경의 순위가 미래의
> 실제 칩 결과 순위를 예측해야만 **검증된 시뮬레이터**라고 부를 수 있습니다.

### 화면 F — 아직 모르는 것

“정답 없는 공개 질문”이라는 제목의 accordion 여섯 개를 둔다. 각 질문에는
`왜 중요한가`와 `무슨 증거가 답이 되는가`만 쓴다.

1. 공개 도구의 PPA 순위가 실제 배치·배선 뒤에도 유지되는가?
   - 증거: 같은 후보들의 합성 순위와 routed 순위 상관관계
2. 공개 공정에서 배운 정책이 다른 공정에서도 통하는가?
   - 증거: 보지 못한 PDK·block family holdout
3. 테스트와 정형 속성의 빈틈을 어떻게 지속적으로 찾을 것인가?
   - 증거: mutation kill rate와 새 counterexample
4. AI는 모를 때 멈추거나 사람에게 넘길 수 있는가?
   - 증거: abstain 품질과 hard-failure 감소
5. offline 점수가 미래 실제 결과를 예측하는가?
   - 증거: 사전에 고정한 policy 순위와 이후 결과의 상관관계
6. 공개 자료의 평가·학습·파생물 권리는 각각 허용되는가?
   - 증거: 출처별 rights receipt와 삭제/revocation test

하단 문구:

> 이 페이지는 공개 도구로 확인할 수 있는 학습 원리를 설명합니다. 실제 제조
> 가능성, 상용 signoff, 회사 데이터의 학습 효용은 증명하지 않습니다.

## 4. 콘텐츠 표현 원칙

- 한 문단은 최대 3문장, 한 문장은 가능한 25어절 이내.
- 처음에는 쉬운 한국어를 쓰고 기술 용어는 괄호로 한 번만 병기한다.
  - 논리합성(synthesis), 배치·배선(place & route), 정형검증(formal verification)
- PPA는 처음 등장할 때 `전력·속도·면적`로 풀어 쓴다.
- `OBSERVED`, `HYPOTHESIS`, `NOT YET` 배지를 콘텐츠 근처에 붙인다.
- “칩을 자동으로 설계한다”, “실리콘 결과를 예측한다” 같은 확정 표현은 쓰지 않는다.
- 특정 회사·국가·파트너·구매·시장 규모·로드맵을 언급하지 않는다.

## 5. 시각·접근성

- 분위기: 투자 덱보다 과학관의 인터랙티브 전시. 밝은 배경, 선명한 회로선,
  제한된 강조색.
- 상태를 초록/빨강만으로 구분하지 않고 `통과/실패` 텍스트와 아이콘을 병기한다.
- 모든 탭·사다리·accordion·데모는 키보드로 조작 가능해야 한다.
- tab에는 `aria-selected`, 결과 변화에는 `aria-live="polite"` 의미를 요구한다.
- `prefers-reduced-motion`에서는 회로선 애니메이션을 제거한다.
- 모바일에서는 사다리를 가로 스크롤시키지 않고 accordion으로 바꾼다.
- 숫자 애니메이션은 자동 재생하지 않으며 사용자가 `실행`을 눌러야 시작한다.

## 6. 완료 기준

사용자 테스트 5명 중 4명 이상이 페이지를 본 뒤 다음 세 질문에 답할 수 있어야 한다.

1. simulator, data, feedback은 각각 무엇인가?
2. 공개 테스트 만점이 왜 충분하지 않은가?
3. 언제부터 “검증된 simulator”라고 부를 수 있는가?

페이지 분석은 개인 식별 없이 다음만 본다.

- 세 재료를 모두 연 비율
- reward hacking 데모의 hidden test까지 실행한 비율
- 사다리에서 3단계 이상 탐색한 비율
- 공개 질문을 하나 이상 연 비율

회원가입, 연락처 수집, 파트너 문의 CTA는 두지 않는다.
